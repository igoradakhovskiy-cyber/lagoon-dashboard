# Lagoon Resort — живой рекламный дашборд

Интерактивный отчёт по рекламе Meta (Facebook / Instagram) для проекта Lagoon Resort.
Данные тянутся из рекламного кабинета **Homex** (`act_1304695957188832`) через Meta Marketing API
**и** из выгрузки CRM в Google-таблице, джойнятся по UTM-меткам, обновляются каждые 3 часа и
публикуются на GitHub Pages за паролем.

## Что внутри
- KPI: расход, лиды, CPL, **квал-лиды, цена квал-лида (CPQL), % квала** + план/факт месяца.
- Полоса качества данных: сколько строк CRM удалось сопоставить с рекламой и почему остальные — нет.
- Динамика по дням, воронка (показы → клики → лиды → квалы), потоки **EN / RU** с CPQL.
- **География** — полный P&L по странам: расход, лиды, CPL, квалы, CPQL, % квала.
- **Этапы сделок** из CRM.
- Кампании с дрилл-дауном: кампания → адсет → объявление, с квалами и CPQL **на каждом уровне**.
- **Галерея креативов** — постеры 9:16, сортировка по квалам / CPQL, живое превью Meta в модалке.

## Стек
Vite + React + TypeScript + Tailwind v4 + Recharts. Данные — один зашифрованный файл
`public/data/latest.enc` (AES-256-GCM, ключ из пароля через PBKDF2). Сборщики — Node 18+
без внешних зависимостей.

## Локально
```bash
npm install
npm run data       # Meta + CRM + шифрование одной командой
npm run dev        # http://localhost:5180/lagoon-dashboard/
```

`npm run data` = `fetch-meta.mjs` → `fetch-crm.mjs` → `encrypt-data.mjs`.
Для шифрования нужна переменная `DASHBOARD_PASSWORD`.
Токен Meta берётся из `~/.config/claude-meta/token.env` или из `META_ACCESS_TOKEN`.

## Как обновляются данные

Каждые 3 часа GitHub Actions запускает оба сборщика **в одном прогоне**, поэтому реклама
и CRM всегда из одного среза и не расходятся между собой.

**Meta** — `scripts/fetch-meta.mjs`, Graph API. Настройки: `META_ACCOUNT_ID`, `MIN_DATE`,
`LEAD_TYPE`, `PLAN_BUDGET`, `PLAN_LEADS`, `PLAN_CPL`, `PLAN_QUAL`, `PLAN_CPQL`, `PREVIEW_FORMAT`.

**CRM** — `scripts/fetch-crm.mjs` читает первую вкладку Google-таблицы обычным `fetch`
CSV-экспорта. Таблица открыта на чтение по ссылке, поэтому **не нужны** ни OAuth, ни сервисный
аккаунт, ни API-ключ. Настройки: `SHEET_ID`, `SHEET_TAB`, `QUAL_VALUE`.

Страница показывает срез на момент последней сборки (максимум 3 часа), браузер клиента
в Google не ходит. Нужно прямо сейчас — кнопка **Run workflow** в Actions, ~2 минуты.

### Как устроен джойн

Лендинг прокидывает в CRM макросы Meta, поэтому в выгрузке лежат **ID, а не названия**:

| в CRM | что это | где |
|---|---|---|
| `utm_id` | `{{campaign.id}}` | колонка L |
| `utm_term` | `{{adset.id}}` | колонка M |
| `utm_content` | имя объявления | внутри URL в колонке **H (Referer)** |

Джойн по ID — поэтому он точный и **переживает переименование кампании**, в отличие от
джойна по названиям. Названием (`utm_campaign`, колонка N) пользуемся только как запасным ключом.

Отдельная колонка «UTM Content» (J) для этого **непригодна**: у RU-кампаний она пустая, а у EN
Google приводит её к числу, и объявление `01` приезжает как `1`. В Referer сохраняется исходная
строка запроса, поэтому `utm_content` берётся оттуда, а колонка J — только последний фолбэк.

**Квал-лид** — значение `квал` в **колонке O** («Квал»). Колонки читаются **по индексу, а не по
имени**: в выгрузке несколько почти одинаковых UTM-колонок, и поиск по имени однажды возьмёт не ту.

Строки, которые не удалось сопоставить, не выбрасываются молча — они попадают в блок
`unmatched` с причиной и видны в интерфейсе.

### Две географии — это важно

В таблице «География» **расход и лиды берутся из Meta** (`breakdowns=country`) — это страна, где
объявление **показали**. **Квалы берутся из CRM** — это страна, записанная менеджером в карточке
сделки. Обычно они сходятся (на срезе 29.07.2026 расхождение ≤ 3 лида на страну при 94 против 95
лидов в сумме), но человек мог кликнуть из поездки.

Страны, где реклама **не крутилась вообще**, вынесены отдельным блоком под таблицей: расход к ним
не относится, поэтому CPQL для них не считается — иначе он вышел бы $0 и врал.

Русские названия стран ↔ ISO-коды живут в `scripts/countries.mjs`. `США / Канада` — намеренный
псевдокод `US_CA`: в CRM это один общий пункт, разделить его задним числом нельзя.

### Проверки

`fetch-meta.mjs` падает, если страновой срез разошёлся с ad-level больше чем на 1% расхода
или на 2 лида — это две независимые выборки одного окна, и они обязаны сходиться.

`fetch-crm.mjs` падает, если сломалось что-то структурное: изменилась шапка, ноль строк в окне,
match-rate ниже 50%, больше 10% нераспознанных стран.

Это важно, потому что **gviz не отдаёт 404 на неверное имя вкладки — он молча возвращает
первую вкладку**. Без проверки шапки пайплайн зашифровал бы мусор и никто бы не заметил.

```bash
npm run crm:verify   # сверка с эталонным срезом 29.07.2026
```

## Деплой (GitHub Pages + авто-крон)
1. Репозиторий **`lagoon-dashboard`** (имя важно — под него настроен `base` в `vite.config.ts`).
2. Settings → Pages → Source = **GitHub Actions**.
3. Settings → Secrets and variables → Actions:
   - Secret `META_ACCESS_TOKEN` — системный токен Meta.
   - Secret `DASHBOARD_PASSWORD` — пароль входа в дашборд.
   - Variable `META_ACCOUNT_ID` = `act_1304695957188832`.
   - Variable `SHEET_ID` — **необязательно**, скрипт по умолчанию берёт таблицу Lagoon.
4. `git push` → workflow соберёт и опубликует сайт, дальше пересборка каждые 3 часа.

Итоговая ссылка: `https://<user>.github.io/lagoon-dashboard/`

## Безопасность
Расшифровка происходит в браузере: неверный пароль — данные просто не расшифруются,
обойти через DevTools нечего. В репозиторий не попадают ни токен, ни `.data/latest.json`,
ни постеры — всё пересобирается в CI при каждом прогоне.

Отдельно стоит держать в голове: сама Google-таблица сейчас **читается любым, у кого есть
ссылка**. Если закрыть доступ, сборка упадёт — тогда нужен сервисный аккаунт + Sheets API
с JSON-ключом в GitHub Secrets.

## Оговорка по квал-лидам
В выгрузке есть только дата создания лида, даты квалификации нет. Квал привязан к дате
создания, поэтому цифры за последние дни ещё дорастут — свежий CPQL всегда выглядит хуже,
чем окажется через неделю.
